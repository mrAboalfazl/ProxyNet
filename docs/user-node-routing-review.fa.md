# بررسی روند کاربر، سرورها و مسیریابی

> این گزارش وضعیت پیش از اجرای مدیریت نود خصوصی را ثبت می‌کند. قابلیت‌های اجراشده و ترتیب انتشار جدید در [راهنمای مدیریت نود](node-management.fa.md) آمده است.

تاریخ: ۲۰۲۶-۱۱-۱۵ — بررسی کد محلی؛ نصب روی سرور واقعی و آزمون محیط production انجام نشده است.

## نتیجه و تصمیم پیشنهادی

محصول فعلی دو مسیر مستقل دارد: HTTP Gateway/Forwarder با انتخاب نود در سرور، و SOCKS5 با اتصال مستقیم کلاینت به آدرس نود. فرم‌ها باید همین تفکیک را نشان بدهند. «سرور ثبت‌شده توسط من» با «نود انحصاری برای من» متفاوت است. فعلاً مدل دوم پیاده‌سازی نشده و نباید وعده آن در رابط داده شود.

## رفتار موجود و اصلاحات انجام‌شده

- عنوان نودهای اختصاصی به «سرورهای ثبت‌شده من» تغییر کرد. ثبت‌کننده مالک انحصاری ترافیک نیست؛ نود تأییدشده وارد استخر اشتراکی می‌شود.
- مراحل ثبت، نصب ایجنت و انتظار تأیید در صفحه کاربر توضیح داده شد؛ وضعیت pending به «در انتظار نصب» و «در انتظار تأیید» تفکیک نمایشی شد.
- IP، نام میزبان، سیستم‌عامل و تعداد هسته ساختگی از صفحه حذف شدند. نبود داده با مقدار خالی/گزارش‌نشده نمایش داده می‌شود؛ کپی IP و راهنمای اتصال پیش از وجود آدرس/فعال‌سازی مسدود شدند.
- تأیید نود در بک‌اند فقط برای نود pending با ایجنت ثبت‌شده مجاز شد؛ دکمه تأیید ادمین قبل از ثبت ایجنت غیرفعال است. این شرط هنوز جای تست دسترس‌پذیری سرویس را نمی‌گیرد.
- پاسخ فهرست نودهای خود کاربر دیگر hash رمز نود، رمز رمزگذاری‌شده رله یا توکن نصب را برنمی‌گرداند؛ فقط enrolled را نشان می‌دهد.
- مسیرهای عمومی JWT برای فهرست و جزئیات مدیریتی نودها و snapshot/بازسازی مسیریابی به دسترسی ادمین محدود شدند. مسیر snapshot ایجنت همچنان احراز هویت نود دارد.
- انتخاب و فهرست نودهای خروجی HTTP اکنون نقش exit را هم بررسی می‌کند.
- تنظیم پروفایل به «مسیریابی پیش‌فرض HTTP» تغییر نام داد و دامنه اثر آن روشن شد؛ کشور انتخابی فورواردر یا درخواست Gateway بر پروفایل مقدم است. SOCKS5 مستقیم از این تنظیم پیروی نمی‌کند.
- اگر حالت قدیمی local ذخیره شده باشد، پروفایل آن را توضیح می‌دهد و به‌صورت پنهانی به auto تغییرش نمی‌دهد.
- کنترل‌های انتخاب حالت و کشور پروفایل با دکمه قابل استفاده با صفحه‌کلید شدند؛ کشورهای غیرفعال در فرم‌ها فیلتر شدند.

## روند مطلوب کاربر

### استفاده عادی بدون سرور شخصی

۱. کاربر پروژه می‌سازد و از دکمه مشترک افزودن، HTTP یا SOCKS5 را انتخاب می‌کند.
۲. HTTP: نام و URL مقصد الزامی؛ مسیر پیش‌فرض حساب یا کشور مستقل؛ گزینه‌های مسیر/query/Authorization در تنظیمات پیشرفته.
۳. SOCKS5: ساخت اعتبارنامه، ذخیره Secret یک‌بارنمایش، انتخاب آدرس نود و کپی پیکربندی واقعی. عنوان Auto و ادعای IP ثابت نباید نمایش داده شود.
۴. فرم باید پیش‌نیاز مصرف را دقیق نشان دهد: اعتبار کیف پول برای HTTP، اشتراک/سهمیه برای SOCKS5. همین حالا این دو مسیر قوانین یکسان ندارند.
۵. سرورهای ثبت‌شده یک قابلیت اختیاری در بخش پیشرفته است و نباید مرحله اجباری راه‌اندازی پروکسی به نظر برسد.

### افزودن سرور متعلق به کاربر

۱. نام قابل تشخیص، کشور واقعی، توضیح صریح اشتراکی بودن پس از تأیید.
۲. نمایش دستور نصب یک‌بارمصرف، زمان انقضا، سیستم‌عامل/معماری پشتیبانی‌شده و پیش‌نیاز sudo.
۳. نمایش مجزای نصب ایجنت، آخرین تماس، نسخه و وضعیت بررسی ادمین.
۴. فعال‌سازی پس از تأیید مدیریتی و تست واقعی سرویس خروجی؛ صرف heartbeat کافی نیست.
۵. راهنمای اتصال فقط با endpoint واقعی و سازگار با پروتکل؛ پورت نباید از روی حدس تولید شود.

| P1 | اعتبارسنجی ثبت سرور | کشور فعال و کد معتبر، نام با طول محدود و نقش‌های مجاز در بک‌اند اعتبارسنجی شوند؛ ثبت اولیه کاربر فقط exit باشد. |
| P1 | صف بررسی ادمین | تفکیک نصب‌نشده/در انتظار بررسی؛ نمایش کشور اعلامی و تشخیص‌داده‌شده، IP، نسخه، آخرین تماس، نتیجه تست و مالک/ثبت‌کننده؛ رد با دلیل قابل مشاهده برای کاربر. |
| P1 | تست اتصال از صفحه پروژه | درخواست تشخیصی محدود با کشور و IP خروجی واقعی، زمان پاسخ و دلیل شکست؛ مشخص باشد آیا تست هزینه دارد. نتیجه به همان رکورد و مسیر مربوط باشد. |
| P2 | گزارش تصمیم مسیریابی | نمایش تنظیم مؤثر، منبع آن (درخواست/فورواردر/پروفایل)، نود استفاده‌شده و تلاش‌های ناموفق؛ بدون افشای Secret و Authorization. |
| P2 | عملیات ادمین و ممیزی | ثبت عامل و علت تأیید/رد/غیرفعال‌سازی، drain برای توقف اتصال جدید، تاریخچه نسخه و نتیجه آپدیت، فیلتر بر اساس مالک/نقش/سلامت. |
| P2 | فرم پیکربندی SOCKS5 | انتخاب endpoint معتبر دارای نسخه سازگار و پورت برگشتی API؛ نمایش لینک مخصوص کلاینت و وضعیت نیاز به پلن؛ حذف اتکا به پورت ثابت راهنما. |

این موارد برنامه پیشنهادی‌اند و به‌جز اصلاحات صریح بخش قبل، در این تغییر پیاده‌سازی نشده‌اند. اجرای نود خصوصی نیازمند تغییر مدل داده و سیاست دسترسی است.

## قواعد روشن برای پروفایل

- Auto: توزیع درخواست‌های HTTP بین نودهای واجد شرایط؛ نه تضمین بهترین کشور یا ثابت ماندن IP.
- کشور ثابت: جابه‌جایی فقط بین نودهای همان کشور؛ نبود مسیر باید خطا بدهد، نه خروج بی‌اطلاع از کشور دیگر.
- تنظیم کشور روی فورواردر/درخواست Gateway، پیش‌فرض حساب را override می‌کند.
- حالت local در بک‌اند وجود دارد: خروج مستقیم از سرور پنل. برای کاربر عادی لازم نیست به‌عنوان گزینه پیشنهادی عرضه شود؛ مقدار ذخیره‌شده باید توضیح داده شود.
- رفتار fallback فعلی بین HTTP Gateway و فورواردر کاملاً یکسان نیست: فورواردر در Auto و نبود کاندیدا مسیر مستقیم دارد؛ Gateway تابع allowLocalFallback است. پیش از ارائه سوییچ «تغییر مسیر خودکار» باید این سیاست یکسان و قابل مشاهده شود.
- انتخاب کشور به معنی انتخاب نود مشخص یا IP ثابت نیست. برای رزرو نود و IP باید قابلیت مجزا با مجوز واقعی ساخته شود.

## شواهد کد

- apps/control-plane/src/nodes/nodes.service.ts: ثبت‌کننده، enrollment، approve و heartbeat.
- apps/control-plane/src/routing/routing-snapshot.service.ts: استخر مشترک؛ سیاست‌ها در snapshot حمل می‌شوند، اما این به‌تنهایی اجرای آن‌ها در selector نیست.
- apps/control-plane/src/routing/node-selector.service.ts: اولویت کشور درخواست/پروفایل و انتخاب نود؛ فعلاً تخصیص خصوصی یا فیلتر پلن در آن نیست.
- apps/control-plane/src/forwarders/forwarders.service.ts: resolveCountries و اعتبارسنجی کشور فورواردر.
- apps/control-plane/src/forwarders/forwarder-proxy.controller.ts: اولویت کشور رکورد، انتخاب کاندیدا و fallback.
- apps/control-plane/src/gateway/gateway.service.ts: اولویت تنظیم درخواست، failover و allowLocalFallback.
- apps/control-plane/src/proxy-credentials/proxy-credentials.service.ts و nodes/nodes.controller.ts: فهرست endpoint در برابر تأیید credential؛ مجوز نود/کشور در تأیید فعلی بررسی نمی‌شود.
- scripts/install.sh: نصب Linux، دسترسی root، سرویس‌ها و پورت‌های فایروال.

## اعتبارسنجی

۱۲ تست در سه مجموعه پاس شدند: گزینه‌های فوروارد، انتخاب نود و مرزهای ثبت/تأیید/دسترسی نود. TypeScript وب پاس شد. بررسی کامل TypeScript بک‌اند پاس نشد: تنظیم فعلی فایل‌های تست را با types فقط node می‌خواند و علاوه بر نام‌های Jest، خطاهایی در admin.service، plans.controller، users.controller و users.service وجود دارد. تست موفق به معنی تأیید شبکه زنده یا نصب production نیست.
