## اصلاح آپدیت و نصب

روش قبلی تلاش می‌کرد از داخل سرویس محدود رله روی فایل‌سیستم فقط‌خواندنی بنویسد و روی دو نود عمومی با EROFS شکست می‌خورد. این روش حذف شد.

سرویس جداگانه `proxynet-relay-update.service` با تایمر `proxynet-relay-update.timer` نصب شد. رلهٔ اصلی همچنان محدود می‌ماند. updater فقط از پنل تنظیم‌شده و مسیر ثابت همان نود آرتیفکت می‌گیرد، checksum و صحت JavaScript را بررسی می‌کند و پس از جایگزینی اتمی، سرویس مشخص رله را ری‌استارت می‌کند. در صورت شکست ری‌استارت، فایل قبلی بازگردانده می‌شود. خطای گزارش وضعیت پس از آپدیت موفق باعث بازگشت بی‌دلیل نسخه نمی‌شود.

پوشه تنظیمات و فایل‌های credential به مالکیت root و دسترسی خواندن گروه سرویس تغییر کردند تا سرویس کم‌اختیار نتواند مقصد دانلود updater را تغییر دهد. پشتیبانی از تنظیمات قدیمی `agent.json` نیز برقرار است.

دستور نصب پنل اکنون از `/api/nodes/install.sh` دریافت می‌شود. خود رله و updater بعد از ثبت اولیه نود، از مسیرهای نیازمند احراز هویت نود دانلود و checksum می‌شوند. برای این جریان به انتشار تغییرات در GitHub وابسته نیستیم؛ مخزن عمومی در این کار push نشده است.

- دریافت updater و فهرست نود بدون اعتبارنامه: HTTP 401.
- اجرای بخش دانلود installer با اعتبار نود موجود در پوشه موقت، تطبیق هر دو فایل و بررسی syntax موفق؛ نود آزمایشی در دیتابیس production ساخته نشده است.
