# مدیریت نود کاربر و استفاده در پروژه

> به‌روزرسانی انتشار: نسخه روی سرور فعال شده است؛ نتیجه نهایی و تغییر مسیر نصب در [گزارش انتشار](deployment-20261116.fa.md) ثبت شده است.
این تغییر در کد محلی اجرا شده است؛ انتشار روی پنل و سرورهای واقعی جزو کار انجام‌شده نیست.

## روند کاربر

۱. در `/user/nodes` نام، کشور واقعی و سطح دسترسی سرور را انتخاب می‌کند. پیش‌فرض «فقط حساب من» است. انتخاب اشتراک عمومی صرفاً یک درخواست ایجاد می‌کند و نود تا زمان تأیید ادمین خصوصی می‌ماند.
۲. دستور نصب یک‌بارمصرف را روی سرور خودش اجرا می‌کند. اگر دستور را ببندد یا توکن منقضی شود، برای نود نصب‌نشده می‌تواند دستور تازه بگیرد؛ توکن قبلی دیگر معتبر نیست. دریافت هم‌زمان یک توکن نصب، دو نود با دو رمز ایجاد نمی‌کند.
۳. نود ثبت‌شده توسط کاربر تا تأیید اولیه ادمین در انتظار می‌ماند. تأیید خصوصی آن را عمومی نمی‌کند. تأیید درخواست اشتراک، نود را وارد شبکه عمومی می‌کند.
۴. پس از ثبت رله و فعال‌شدن نود، دکمه «استفاده در پروژه» پروژه را انتخاب می‌کند و فرم افزودن با همان نود باز می‌شود.
۵. در فرم پروژه، SOCKS5 یا HTTP انتخاب می‌شود. ذخیره نود خروجی در هر دو نوع واقعی است؛ نبود نود یا پس‌گرفتن دسترسی باعث خطا می‌شود و نود دیگر جایگزین نمی‌شود.
۶. از مدیریت نود می‌تواند نام را تغییر دهد، مصرف را متوقف/ادامه دهد، درخواست آپدیت رله بدهد، درخواست عمومی‌شدن ثبت کند یا اشتراک را لغو کند. توقف توسط مالک مستقل از وضعیت ادمین است؛ ادامه استفاده نود غیرفعال یا قرنطینه‌شده را فعال نمی‌کند.

## دسترسی و مصرف

- نود خصوصی فقط برای حساب ثبت‌کننده قابل انتخاب و استفاده است؛ عمومی‌بودن نیاز به اقدام صریح ادمین در پاسخ به درخواست صاحب نود دارد.
- فهرست انتخاب نود، endpointهای SOCKS5، انتخاب HTTP و تأیید SOCKS5 همگی مجوز حساب را بررسی می‌کنند. انتخاب HTTP روی وضعیت زنده دیتابیس کنترل می‌شود تا snapshot قدیمی، توقف یا خصوصی‌شدن نود را دور نزند.
- نود باید exit و active/healthy باشد، کشور فعال داشته باشد و توسط کاربر متوقف نشده باشد. برای HTTP علاوه بر این، رله ثبت‌شده و آدرس لازم است.
- محدودیت کشور پلن فعال برای انتخاب نود و مسیر HTTP نیز اعمال می‌شود. سازوکار کیف پول HTTP حفظ شده است؛ برای SOCKS5 پلن فعال، بازه معتبر اشتراک و سهمیه همچنان لازم است، حتی روی نود شخصی.
- اعتبارنامه SOCKS5 متصل به نود فقط روی همان نود کار می‌کند. اعتبارنامه بدون نود مشخص روی نودهای مجاز حساب قابل استفاده است. اعتبارنامه متصل به نود برای احراز هویت Gateway عمومی پذیرفته نمی‌شود و به سرور VLESS عمومی اضافه نمی‌شود.
- ورود SOCKS5 جدید در هر اتصال از پنل مجوز می‌گیرد؛ کش قبلی احراز هویت حذف شده است. رله جدید اتصال‌های باز را هر ۲۰ ثانیه بازبینی می‌کند؛ با timeout درخواست ۱۰ ثانیه، لغو مجوز تقریباً حداکثر طی ۳۰ ثانیه اعمال می‌شود. نرسیدن پاسخ پنل نیز اتصال را می‌بندد.
- درخواست HTTP که قبل از توقف آغاز شده ممکن است تا پایان اجرا شود؛ توقف برای درخواست‌های جدید اعمال می‌شود.
- عمومی به معنی پراکسی بدون رمز نیست؛ احراز هویت و سهمیه کاربران حفظ می‌شود.
- snapshot تحویلی به ایجنت، نودهای خصوصی دیگر حساب‌ها را شامل نمی‌شود. فهرست مدیریتی و بازسازی snapshot نیاز به دسترسی ادمین دارند.

## ادمین

صف بررسی شامل نود نصب‌شده در انتظار تأیید اولیه و درخواست اشتراک نود فعال است. دکمه تأیید نوع درخواست را نشان می‌دهد. رد اشتراک برای نود از قبل فعال، نود خصوصی صاحب آن را غیرفعال نمی‌کند. تأیید هم‌زمان با لغو درخواست توسط صاحب نود، اجازه انتشار نمی‌دهد.

توکن، نصب ایجنت و تأیید مدیریتی جای بررسی مستقل کشور واقعی و تست سلامت سرویس از بیرون را نمی‌گیرند. تشخیص خودکار مکان، مانیتورینگ فعال سرویس و گزارش علت رد همچنان توسعه بعدی‌اند؛ این تغییر ادعای اجرای آن‌ها ندارد.

## ترتیب انتشار

۱. از دیتابیس نسخه پشتیبان تهیه شود و migration `20261115120000_node_ownership` همراه migrationهای قبلی پروژه اجرا شود. نودهای پلتفرم عمومی می‌مانند؛ تمام نودهای ثبت‌شده توسط کاربران، با هدف جلوگیری از اشتراک بدون رضایت، خصوصی می‌شوند.
۲. Prisma Client تولید و API جدید منتشر شود. کد API جدید بدون migration قابل اجرا نیست.
۳. رله‌ها به نسخه `2026.11.15.1` یا جدیدتر ارتقا و ری‌استارت شوند. ری‌استارت، اتصال‌های باقی‌مانده از رله قدیمی را می‌بندد. پیش از این مرحله، نباید قطع دوره‌ای اتصال‌های قدیمی را تضمین کرد.
۴. snapshot مسیریابی بازسازی و پنل جدید منتشر شود. برای عمومی‌کردن مجدد نودهای کاربر، درخواست و تأیید صریح انجام شود.
۵. نصب‌کننده عمومی هنوز فایل‌ها را از شاخه GitHub دریافت می‌کند؛ انتشار سورس/بسته رله جدید نیز برای نصب‌های آینده لازم است. صرف تغییر پنل، نسخه موجود روی سرور کاربر را به‌روز نمی‌کند.

این مراحل انتشار در این نوبت روی محیط واقعی انجام نشده‌اند.

## اعتبارسنجی محلی

Migration روی PostgreSQL 16 جدا از دیتابیس برنامه اجرا شده است. تست‌های دیتابیس شامل مالکیت، انتخاب نود در هر دو نوع رکورد پروژه، تأیید و لغو اشتراک، کنترل snapshot قدیمی، جلوگیری از تغییر نود مخفی، سهمیه کشور و جلوگیری از استفاده مجدد توکن هستند. تست شبکه رله شامل احراز هویت واقعی SOCKS5 و بسته‌شدن اتصال باز بعد از لغو دسترسی است. ۲۷ تست کنترل‌پلین (شامل ۱۴ تست دیتابیس واقعی) و ۲ تست شبکه رله پاس شدند. بیلد تولیدی وب موفق است.

بررسی کامل TypeScript بک‌اند همچنان خطاهای قبلی تنظیمات تایپ تست‌ها و چند ماژول دیگر را گزارش می‌کند؛ موفقیت تست‌های این قابلیت معادل موفقیت بیلد کامل بک‌اند یا تأیید شبکه production نیست.
